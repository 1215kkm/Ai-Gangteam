# 상상의 문 — "마지막 한 칸을 푸는 열쇠" (강팀 오리지널 제안서)

외주 덱을 수정한 게 아니라, **강팀이 아뱅(마케팅) 주도로 처음부터 새로 만든** 웹 제안서입니다.

- **열기**: `report/index.html` 를 브라우저로 열면 됩니다. 단일 HTML(스크롤형 7섹션), 이미지 자산은 `report/assets/`.
- **디자인**: 강팀 하우스 스타일 #1 Crowny Class (보라→분홍). 토큰 정본 `.claude/knowledge/ui-designer/styles/tokens.css`.

## 핵심 컨셉 (아뱅)
**"빈 칸 = 손실."** 점주의 진짜 적은 재미없는 테마가 아니라 *평일 낮·조조·심야의 빈 슬롯*. 제안서는 "예쁜 사이트"가 아니라 **빈 슬롯을 돈으로 바꾸는 장치**를 판다.

## 7섹션 흐름 (통증 → 정체 → 진단 → 해법 → 오퍼 → 측정 → 결정)
1. **표지** — "마지막 한 칸을 푸는 열쇠"
2. **진짜 문제** — 주간 예약 히트맵. 채운 슬롯만 그라데이션, 빈칸은 무채색(₩) = 손실 시각화
3. **정직 진단** — "잘했다" 대신 결제 불일치(안내 2만원 ↔ 전액 청구)를 신뢰 자본으로. 동작/불일치/미구현 3색 체크리스트
4. **해법** — 이미 있는 할인 슬롯에 실시간 "지금 특가 · 남은 1팀" 펄스 배지
5. **오퍼** — 3단계 가격 사다리(새는곳 막기 → 진짜 예약 → 더 벌기), 가격은 숫자 대신 구조(₩___)
6. **정직 KPI** — 근거 없는 수치 안 씀. "측정 예정" + 측정법(GA 2주 기준선 → A/B)
7. **결정(CTA)** — "가장 어려운 방은 시작 버튼 앞에서 멈춘 손님" + 확정 필요 4가지 박스

## 발송 전 확정 필요 4가지 (본문 신뢰도 보호용으로 분리 표기)
1. 실제 연락처(담당·전화·카카오채널) — 본문 `[입력]` 자리
2. 지점 수 — 푸터 7 vs 예약 6
3. 예약금 정책 — 2만원 선결제 vs 전액 청구
4. 결제 PG사 / 제3자 제공 고지 범위

## 사실 근거
실제 사이트(`doorlove1234-coder/sangsangDoor`)는 11페이지 동작 데모(순수 HTML, JS+localStorage). 예약·관리자는 돌지만 결제·알림·서버·관리자 인증은 미구현, 잔여석·요금은 "예시" 샘플 — 본문은 이를 정직하게 반영.
